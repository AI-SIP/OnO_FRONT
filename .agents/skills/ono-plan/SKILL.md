# OnO Plan Skill

사용자가 `plan <기능 설명>` 형태로 요청하면 이 Skill을 따른다.

## 목표

기능 구현 전에 다른 에이전트도 바로 참고할 수 있는 구현 개요 및 명세서를 작성한다. 이 단계에서는 앱 코드, 설정 코드, 테스트 코드를 수정하지 않는다.

## 절차

1. 요구사항을 한 문장으로 재정리하고, 해석이 여러 가지면 짧게 확인한다.
2. `docs` 아래 기존 기획/PR/명세 문서를 먼저 확인한다.
3. 현재 코드 흐름, 상태 관리, 라우팅, API 연동 위치를 읽어서 근거를 확보한다.
4. 백엔드 API 계약, 응답 필드, null 가능성, 에러 형태가 불명확하면 임의로 단정하지 않는다.
5. `docs` 아래에 기능을 알아볼 수 있는 새 폴더를 만든다. 폴더명은 기존 문서처럼 한글 중심으로 짧게 작성한다.
6. 새 폴더 안에 markdown 명세서를 작성한다.

## 명세서 필수 항목

- 기능 목표
- 사용자 영향
- 화면 흐름
- 수정 예상 파일과 역할
- API/상태 관리 영향
- null/빈 상태/에러 상태 처리
- 폰/태블릿/가로세로 반응형 고려사항
- 배포 리스크
- 검증 방법
- 이후 `feat` 단계에서 수행할 구체적인 작업 순서
- 추천 커밋 단위와 커밋 메시지 초안

## 금지

- 구현 코드 수정
- 테스트 코드 추가
- 불필요한 구조화나 미래 확장용 설계
- 확인되지 않은 API 필드명 또는 응답 구조 작성

## 완료 보고

작성한 문서 경로, 핵심 결정, 남은 확인사항을 간결하게 보고한다.

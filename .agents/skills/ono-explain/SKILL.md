# OnO Explain Skill

사용자가 `explain <파일명, 위젯명, 기능 설명>` 또는 코드 설명을 요청하면 이 Skill을 따른다. 인자가 없으면 현재 작업 중인 변경사항(`git status`, staged/unstaged diff, untracked 파일)을 대상으로 흐름과 의도를 설명한다.

## 목표

Flutter에 익숙하지 않은 백엔드 개발자도 이해할 수 있도록 코드 흐름과 설계 의도를 설명한다. 이 단계는 읽기 전용이며, 코드를 수정하거나 커밋하지 않는다.

## 추적 관점

- 위젯 트리: 어느 화면/위젯에서 시작해 어떤 자식 위젯으로 이어지는가
- 상태 관리: 상태가 어디서 정의되고, 어디서 바뀌며, 어디서 UI에 반영되는가
- API 호출: UI 이벤트에서 서비스/레포지토리/HTTP 클라이언트를 거쳐 어느 엔드포인트로 가는가
- 에러/로딩/빈 상태: 사용자가 보는 상태가 어디서 결정되는가
- Flutter 관용 패턴: `StatefulWidget`, `Provider/Riverpod/Bloc`, `FutureBuilder`, `LayoutBuilder` 등 해당 코드 이해에 필요한 개념

## 절차

1. 사용자가 지정한 파일, 위젯, 기능명을 기준으로 진입점을 찾는다. 인자가 없으면 현재 변경된 파일을 진입점으로 삼는다.
2. 호출 경로와 데이터 흐름을 `파일:라인` 근거로 추적한다.
3. 실행 순서대로 단계별 흐름을 설명한다.
4. 왜 이렇게 구현되어 있는지, 어떤 제약과 트레이드오프가 있는지 설명한다.
5. 수정 시 특히 조심해야 할 부분을 정리한다.

## 보고 형식

```markdown
## 흐름 요약
1. 파일:라인 - 설명
2. 파일:라인 - 설명

## 상태와 데이터 흐름
- ...

## 핵심 설계 이유
- ...

## 주의할 동작
- ...

## Flutter 개념 메모
- ...
```

## 설명 원칙

- 어려운 용어는 짧게 풀어서 설명한다.
- 코드에서 확인된 내용과 추론을 구분한다.
- 학습용 설명이 목적이므로 단순 요약보다 흐름과 이유를 우선한다.
- 코드 수정, 테스트 작성, 커밋은 하지 않는다.

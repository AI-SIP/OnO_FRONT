# OnO Release Skill

사용자가 `release`, `release <기준 커밋>`, `출시 전 검증`, `배포 전 검증`, `업데이트 내역 작성`을 요청하면 이 Skill을 따른다.

## 목표

앱스토어/플레이스토어 제출 전에 현재 변경사항이 배포 가능한지 점검하고, 사용자가 바로 복사해 쓸 수 있는 업데이트 내역을 작성한다. 운영 중인 앱이므로 정적 검증, 사용자 영향, 반응형 UI, 인증/동기화/알림 부작용을 함께 본다.

## 대상 범위

1. 기준 커밋이 있으면 `<기준 커밋>..HEAD`와 현재 uncommitted 변경사항을 함께 확인한다.
2. 기준 커밋이 없으면 최근 릴리즈 이후 범위를 단정하지 않는다. `git log`, `docs/업데이트 내역`, 현재 변경사항을 확인하고 기준이 명확하지 않으면 사용자에게 기준 커밋이나 포함할 기능 범위를 묻는다.
3. 출시 노트만 요청한 경우에도 실제 변경 근거 없이 기능을 과장하지 않는다.

## 절차

1. `git status`, `git log`, 기준 범위 diff를 확인한다.
2. 관련 `docs` 명세서, PR 문서, `docs/업데이트 내역`을 확인해 기능 의도와 사용자 표현을 맞춘다.
3. 가능한 경우 `flutter analyze`를 실행한다.
4. 테스트가 필요한 요청이거나 릴리즈 최종 검증이면 가능한 경우 `flutter test`를 실행한다. 이 프로젝트는 테스트를 별도로 많이 운영하지 않으므로, 테스트가 없거나 실행하지 못한 경우 남은 리스크로 적는다.
5. 변경 파일과 사용자 흐름 기준으로 `ono-check` 수준의 위험 검토를 수행한다.
6. UI 변경이 있으면 작은 폰, 일반 폰, 태블릿, 가로/세로에서 overflow, 버튼 잘림, 스크롤 불가 가능성을 검토한다.
7. 최종 판정과 업데이트 내역 초안을 함께 보고한다.

## 배포 불가 기준

아래 항목 중 하나라도 있으면 `배포 불가`로 판정한다.

- `flutter analyze` 오류 또는 새 경고가 있다.
- 테스트 실패가 있다.
- 런타임 예외, 인증 우회, 데이터 손실, 결제/학습 기록/동기화/FCM 부작용 가능성이 높다.
- 작은 폰이나 태블릿에서 핵심 화면을 사용할 수 없는 UI 깨짐 가능성이 높다.
- API 계약, 응답 필드, null 가능성이 불명확한데 방어 코드가 없다.

## 업데이트 내역 작성 규칙

앱스토어/플레이스토어에 바로 복사할 수 있게 한국어로 작성한다.

- 번호가 있는 기능 목록으로 작성한다.
- 각 기능은 사용자에게 보이는 변화 중심으로 쓴다.
- 초등, 중등, 고등 학생이 이해하기 쉬운 짧은 문장으로 쓴다.
- 내부 구현명, 클래스명, API명, PR 번호, 커밋 해시는 쓰지 않는다.
- "개선했습니다", "추가했어요", "볼 수 있어요"처럼 자연스러운 앱 문구를 쓴다.
- 검증하지 않은 기능, 개발자만 아는 변경, 아직 배포되지 않은 기능은 포함하지 않는다.
- 버그 수정은 사용자가 겪던 문제와 좋아진 점을 짧게 설명한다.
- 같은 흐름의 세부 변경은 하나의 항목 아래 bullet로 묶는다.

예시 형식:

```text
1. 처음 사용자를 위한 튜토리얼 추가

  - OnO의 주요 기능을 처음부터 쉽게 둘러볼 수 있어요.
  - 공책, 오답노트, 복습 세트, 학습 달력, 복습 리포트 사용 흐름을 차례대로 안내해 드려요.
  - 마이페이지에서 튜토리얼을 다시 볼 수 있어요.

2. 여러 장 오답노트 복습 필기 지원

  - 이미지가 여러 장인 오답노트도 앱에서 바로 풀 수 있어요.
  - 각 이미지에 따로 필기하고, 모든 풀이 이미지를 한 번에 제출할 수 있어요.
```

## 보고 형식

````markdown
## 출시 전 종합 검증

### 기준 범위
- 기준 커밋:
- 포함 변경:

### 검증 결과
- `flutter analyze`:
- `flutter test`:
- diff 위험 검토:
- 반응형 검토:

### 배포 판정
- 🟢 배포 가능 / 🔴 배포 불가 / 🟡 확인 후 배포
- 이유:

### 사용자 영향
- ...

### 남은 리스크
- ...

## 업데이트 내역 초안

```text
1. ...
```

## 추천 커밋

```text
[Chore] 출시 전 검증 문서 추가 - 업데이트 내역 정리 배포 리스크 점검
```
````

## 주의

- 실제 앱스토어/플레이스토어 제출, 빌드 업로드, git push, tag 생성은 사용자 요청 없이는 실행하지 않는다.
- 출시 노트를 마케팅 문구처럼 과장하지 않는다.
- 검증을 실행하지 못하면 통과했다고 쓰지 않는다.

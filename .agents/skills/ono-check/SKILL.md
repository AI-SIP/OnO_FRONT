# OnO Check Skill

> 이 파일이 `check` 절차의 정본이다. Codex 는 이 파일을 바로 쓰고, Claude Code 의 `/check` 는 `.claude/skills/check/SKILL.md` 래퍼가 이 파일을 읽어 따른다. 절차를 고칠 때는 이 파일만 고친다.

사용자가 `check <커밋 번호>`(Claude Code 에서는 `/check <커밋 번호>`) 또는 변경사항 검토를 요청하면 이 Skill을 따른다. 인자가 없으면 현재 작업 중인 변경사항(`git status`, staged/unstaged diff, untracked 파일)을 대상으로 검토한다.

## 목표

변경된 파일과 영향받는 사용자 흐름을 기준으로 위험한 사항과 에러 가능성을 검증한다. 전체 프로젝트를 넓게 훑는 대신 diff와 영향 범위에 집중한다. 이 모드는 읽기 전용이라 코드를 수정하거나 커밋하지 않는다.

## 절차

1. 기준 커밋이 있으면 `git diff <커밋>..HEAD` 로 해당 커밋부터 현재까지의 diff를 확인한다.
2. 기준 커밋이 없으면 현재 작업 중인 변경사항을 확인한다. staged, unstaged, untracked 파일을 모두 대상에 포함한다.
3. 변경 파일별 사용자 흐름, 상태 관리, API 연동, UI 영향을 추적한다.
4. 1차 검사는 diff 기반으로 아래 검토 관점을 본다. 서브에이전트를 띄울 수 있는 도구에서는 관점별로 나눠 병렬로 돌린다.
5. 2차 검사는 1차 결론을 스스로 반증한다. 상위 조건, 호출 가능성, 실제 도달 경로를 다시 확인하고, 관점별 결과끼리 겹치거나 어긋나는 것을 정리한다.
6. 가능한 경우 `flutter analyze --no-fatal-infos`(CI 기준, info 제외)를 실행한다. 이 모드는 파일을 바꾸지 않으므로 포맷은 `dart format --output=none --set-exit-if-changed <바뀐 test 파일>` 로 검사만 한다.
7. UI 변경이 있으면 폰과 태블릿 레이아웃에서 깨질 가능성을 직접 검토한다.

## 검토 관점

- 성능: 불필요한 rebuild, jank, 메모리, 긴 리스트
- 로직: null safety와 런타임 예외, async 경합, 상태 전이, 로딩/빈 상태/에러 상태, 에러 처리
- 부작용: API 중복 호출, 로컬 저장, FCM 관련
- 인증과 화면 접근: 로그인, 토큰, 라우팅, 딥링크, 로그아웃 처리가 바뀌었을 때만
- API 계약: 응답 필드, 에러 응답, 백엔드 레포와 맞는지
- 반응형: 작은 폰, 일반 폰, 태블릿, 가로/세로 화면의 overflow와 스크롤 가능성
- 배포: 앱스토어/플레이스토어 배포 후 롤백이 어려운 리스크, 기존 데이터와 학습 기록, 결제/인증/동기화 흐름 영향

## 자가 반증

위험 보고 전에 반드시 아래 질문으로 2차 검토한다.

- 내가 놓쳤을 가능성이 큰 사용자 흐름은 무엇인가
- 이 변경이 실제 사용자에게 깨질 수 있는 경로는 무엇인가
- 이 위험 판단이 틀렸다면 어떤 상위 조건, 라우팅, 상태 값, API 응답 때문에 틀릴 수 있는가
- 문제가 있다고 본 코드가 실제로 실행되는 경로에 도달 가능한가
- 문제가 없다고 본 코드가 null, 빈 응답, 느린 네트워크, 화면 이탈 상황에서도 안전한가

반증 결과 도달 불가능한 문제는 낮추거나 제외하고, 새로 발견된 위험은 위험도에 포함한다.

## 보고 형식

각 항목은 가능한 한 `파일:라인` 근거를 포함한다. 발견한 문제가 없더라도 남은 리스크와 실행하지 못한 검증을 명확히 적는다.

```markdown
## 🔴 즉시 수정 필요
- [파일:라인] 설명

## 🟠 출시 전 수정 권장
- [파일:라인] 설명

## 🟡 주의 필요 (확인 필요, 트레이드오프)
- [파일:라인] 설명

## 🟢 이상 없음
- 확인한 항목 목록

## 실행하지 못한 검증
- ...

## 자가 반증 결과
- ...
```

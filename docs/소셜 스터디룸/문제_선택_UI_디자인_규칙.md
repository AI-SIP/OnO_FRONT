# 문제 선택 UI 디자인 규칙

> 작성일: 2026-06-28
> 대상: 공유할 문제 선택 화면, 복습노트 문제 선택 화면

## 기본 방향

- 공유용 선택과 복습노트 추가용 선택은 정책이 다르므로 상태와 액션은 분리한다.
- 폴더 탐색, 문제 카드, 빈 상태 문구의 시각 규칙만 맞춘다.
- 태블릿과 가로 화면에서는 좌측 탐색 + 우측 목록 구조를 우선한다.
- 폰 세로 화면에서는 상단 폴더 칩 또는 검색 필터 + 하단 문제 목록 구조를 유지한다.

## 폴더 영역

- 폴더 항목은 선택 상태가 한눈에 보여야 한다.
- 선택된 폴더는 `themeProvider.primaryColor` 계열 배경과 진한 텍스트를 사용한다.
- 긴 폴더명은 최대 2줄까지 표시하고, 더 길면 말줄임 처리한다.
- 폰 세로의 폴더 칩은 가로 스크롤을 허용하되, 칩 높이는 40px 안팎으로 유지한다.
- 태블릿의 좌측 폴더 목록은 전체 폭의 약 28~30%를 사용한다.

## 문제 카드

- 문제 썸네일은 고정 비율 영역을 사용해 목록 높이가 흔들리지 않게 한다.
- 이미지 로딩 실패 또는 이미지 없음 상태는 문제 아이콘/연한 배경으로 대체한다.
- 문제 제목은 최대 2줄까지 표시하고, 긴 제목은 말줄임 처리한다.
- 선택 가능한 문제는 카드 전체를 누를 수 있어야 한다.
- 이미 선택한 문제는 체크 아이콘 또는 선택 배경으로 명확히 표시한다.

## 빈 상태와 로딩

- 폴더가 없을 때와 선택 가능한 문제가 없을 때는 서로 다른 문구를 사용한다.
- 빈 상태 문구는 짧게 작성한다.
- 첫 로딩은 화면 중앙 로딩으로, 추가 로딩은 목록 하단 로딩으로 표시한다.
- 네트워크 실패는 조용히 무시하지 않고 스낵바로 알려준다.

## 반응형 기준

- `LayoutBuilder` 기준 `maxWidth >= 600`이면 2단 레이아웃을 검토한다.
- 작은 폰에서는 폴더와 문제 목록을 동시에 2단으로 강제하지 않는다.
- 버튼 영역은 `SafeArea` 또는 하단 padding을 고려해 잘리지 않게 한다.
- 리스트는 긴 텍스트와 많은 항목에서도 스크롤 가능해야 한다.

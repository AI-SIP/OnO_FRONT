## 1. 공유 문제 풀이 의견 API — 필수

### 배경

프론트는 공유 문제를 “다른 사람 문제를 같이 풀기”가 아니라, 공유된 문제를 읽고 룸원들이 풀이 의견을 남기는 흐름으로 바꿨다.

현재 프론트 구현 상태:

- 공유 문제 카드의 “같이 풀어보기” 진입점 제거
- `풀이 의견 보기` 섹션 추가
- 댓글 목록 조회, 작성, 수정, 삭제 UI 선구현
- API 미구현/실패 시 공유 카드 내부에 “풀이 의견을 불러오지 못했어요” 안내 표시

관련 프론트 파일:

- `lib/Model/StudyRoom/SharedProblemCommentModel.dart`
- `lib/Service/Api/StudyRoom/StudyRoomService.dart`
- `lib/Provider/StudyRoomProvider.dart`
- `lib/Screen/StudyRoom/Widget/SharedProblemCard.dart`

### 필요한 엔드포인트

Base URL은 현재 프론트의 `StudyRoomService.baseUrl`과 동일하게 아래 기준을 사용한다.

```text
{BASE_URL}/api/study-room
```

```http
GET /api/study-room/{roomId}/shared-problems/{sharedProblemId}/comments?cursor={cursor}&size=20
```

공유 문제 풀이 의견 목록을 조회한다.

```http
POST /api/study-room/{roomId}/shared-problems/{sharedProblemId}/comments
Content-Type: application/json

{
  "content": "이렇게 풀면 돼요"
}
```

풀이 의견을 작성한다.

```http
PATCH /api/study-room/{roomId}/shared-problems/{sharedProblemId}/comments/{commentId}
Content-Type: application/json

{
  "content": "수정한 풀이 의견입니다"
}
```

본인 풀이 의견을 수정한다.

```http
DELETE /api/study-room/{roomId}/shared-problems/{sharedProblemId}/comments/{commentId}
```

풀이 의견을 삭제한다.

### 응답 형태

프론트는 cursor page 응답과 단순 배열 응답을 모두 파싱할 수 있지만, 기존 공유 문제/피드 API와 맞추려면 cursor page 응답을 권장한다.

권장 목록 응답:

```json
{
  "content": [
    {
      "commentId": 1,
      "content": "이렇게 풀면 돼요",
      "authorId": 123,
      "authorName": "홍길동",
      "authorProfileImageUrl": "https://example.com/profile.png",
      "createdAt": "2026-06-28T10:00:00",
      "updatedAt": "2026-06-28T10:30:00",
      "isEdited": true,
      "isMine": true
    }
  ],
  "nextCursor": null,
  "hasNext": false,
  "size": 20
}
```

작성/수정 응답:

```json
{
  "commentId": 1,
  "content": "이렇게 풀면 돼요",
  "authorId": 123,
  "authorName": "홍길동",
  "authorProfileImageUrl": "https://example.com/profile.png",
  "createdAt": "2026-06-28T10:00:00",
  "updatedAt": "2026-06-28T10:30:00",
  "isEdited": true,
  "isMine": true
}
```

### 필드 규칙

| 필드 | 타입 | 필수 | 프론트 사용 |
|---|---|---|---|
| `commentId` | number | O | 수정/삭제 대상 식별 |
| `content` | string | O | 댓글 본문 표시 |
| `authorId` | number | O | 작성자 식별 |
| `authorName` | string | O | 작성자 이름 표시 |
| `authorProfileImageUrl` | string/null | X | 현재 UI에서는 미사용, 추후 확장 가능 |
| `createdAt` | ISO datetime | O | 작성 시간 표시 |
| `updatedAt` | ISO datetime/null | X | 수정 시간 표시 |
| `isEdited` | boolean | O | “수정” 표시 여부 |
| `isMine` | boolean | O | 수정/삭제 메뉴 노출 여부 |

### 검증/권한

- 스터디룸 멤버만 댓글 조회/작성 가능
- 본인 댓글만 수정 가능
- 삭제 권한은 정책 결정 필요
  - 선택 A: 본인 댓글만 삭제 가능
  - 선택 B: 본인 댓글 또는 방장 삭제 가능
- `content`는 공백만 있으면 거부
- 프론트는 현재 300자 이하로 제한하므로 백엔드도 최대 300자 제한 권장
- 삭제된 공유 문제의 댓글 요청은 `SHARED_PROBLEM_NOT_FOUND` 또는 이에 준하는 에러 반환

### 에러 처리 권장

| 상황 | 권장 HTTP | 권장 코드/메시지 |
|---|---|---|
| 방이 없음 | 404 | `STUDY_ROOM_NOT_FOUND` |
| 방 멤버가 아님 | 403 | `STUDY_ROOM_FORBIDDEN` |
| 공유 문제가 없음 | 404 | `SHARED_PROBLEM_NOT_FOUND` |
| 댓글이 없음 | 404 | `SHARED_PROBLEM_COMMENT_NOT_FOUND` |
| 수정/삭제 권한 없음 | 403 | `SHARED_PROBLEM_COMMENT_FORBIDDEN` |
| 내용이 비어 있음 | 400 | `INVALID_SHARED_PROBLEM_COMMENT` |

## 2. 공유 문제 읽기 전용 정책 보강 — 권장

### 배경

프론트에서는 공유 문제 카드에서 기존 문제 상세/복습 진입점처럼 보이는 동작을 제거했다. 하지만 운영 안정성을 위해 백엔드에서도 “다른 유저가 공유한 문제가 내 복습 세트나 오답노트로 직접 편입되지 않는다”는 정책을 확인하거나 보강할 필요가 있다.

### 확인할 정책

- 공유 문제 목록/카드에서 타인의 원본 문제 이미지를 어디까지 노출할지
- 타인이 공유한 `problemId`로 내 복습 기록 생성 또는 오답노트 편입이 가능한지
- 가능하다면 공유 문제 API 응답에서 타인 문제의 상세 진입에 필요한 민감 필드를 제한할지
- 공유 문제 삭제 후 기존 피드/댓글/반응 데이터 처리 방식

### 프론트 현재 처리

- 공유 문제 카드는 `problemImageUrl`, `reference`, 공유자의 한마디, 반응, 풀이 의견만 표시
- `ProblemDetailScreen`으로 이동하는 동작 제거
- 공유 문제는 룸 안에서 읽고 의견을 남기는 용도로만 사용

## 3. 스터디룸 이름+이미지 통합 수정 API — 선택

### 배경

프론트는 스터디룸 수정 화면에서 이름과 이미지를 한 화면에서 수정할 수 있게 구현했다. 현재 백엔드 API가 이름 수정과 이미지 수정으로 분리되어 있어, 프론트는 아래 순서로 순차 호출한다.

1. 이름 변경 필요 시 `PATCH /api/study-room/{roomId}`
2. 이미지 변경 필요 시 `PATCH /api/study-room/{roomId}/thumbnail`

이 방식은 동작하지만, 이름 수정 성공 후 이미지 업로드 실패 같은 부분 성공 상태가 생길 수 있다.

### 선택 구현안

통합 API가 가능하다면 아래 형태를 요청한다.

```http
PATCH /api/study-room/{roomId}
Content-Type: multipart/form-data

name: string, optional
thumbnailImage: file, optional
```

응답은 기존 `StudyRoomModel` 파싱과 맞게 방 상세 응답 형태를 유지하면 된다.

```json
{
  "roomId": 1,
  "name": "수능 준비방",
  "hostUserId": 42,
  "thumbnailUrl": "https://example.com/thumbnail.png",
  "memberCount": 4,
  "members": []
}
```

### 현재 우회 처리

- 통합 API가 없어도 현재 기능은 사용 가능
- 부분 성공 시 프론트에서 다음 메시지를 보여준다
  - 이름 성공, 이미지 실패: “이름은 변경됐지만 사진 수정에 실패했어요”
  - 이미지 성공, 이름 실패: “사진은 변경됐지만 이름 수정에 실패했어요”

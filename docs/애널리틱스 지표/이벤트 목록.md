# Firebase Analytics 이벤트 목록

> 앱이 Firebase Analytics 로 무엇을 보내는지 한곳에 모은 문서다. 새 기능을 만들 때 여기에 이벤트를 더하고, 콘솔에서 무엇을 봐야 하는지도 여기서 찾는다.
>
> **기준: 새 기능이나 기존 기능 개선을 판단할 수 있는 행동만 남긴다. 누른 순간이 아니라 끝난 순간을 센다.**

관련 코드: `lib/Util/AppAnalytics.dart`, 이슈 #275

---

## 1. 지키는 규칙

| 규칙 | 이유 |
|---|---|
| 새 이벤트는 `AppAnalytics.logEvent(name, params)` 로만 보낸다 | 예외를 삼키고, bool 을 문자열로 바꾸고, 100자 넘는 값을 잘라 준다. `FirebaseAnalytics.instance` 를 직접 부르는 곳은 예전 코드다 |
| 이름은 영어 소문자와 밑줄, 40자 이하 | 규칙을 어긴 이름은 Firebase 가 에러 없이 버린다. 한 번도 콘솔에 들어가지 못한 이벤트가 셋 있었다. `test/util/analytics_event_name_test.dart` 가 막는다 |
| 이름에 값을 붙이지 않는다 | `theme_color_change_to_진핑크` 처럼 붙이면 값마다 이벤트가 따로 생겨 합쳐 볼 수 없다. 값은 파라미터로 보낸다 |
| 성공한 뒤에 남긴다 | 서버 요청 전에 남기면 실패도 센다. 버튼을 누른 것 자체가 궁금하면 `_start`, `_tap` 처럼 이름으로 드러낸다 |
| 파라미터 이름은 아래 사전에 있는 것을 먼저 쓴다 | 콘솔에서 보려면 맞춤 측정기준으로 등록해야 하고 한도가 이벤트 범위 50개다 |
| 사람을 가리키는 값은 보내지 않는다 | 이메일, 이름, 검색어, 댓글 내용, 이미지 주소는 금지다. 길이나 개수만 보낸다 |
| 모든 화면은 `initState` 에서 `AppAnalytics.logScreenView('화면이름')` 을 부른다 | 화면 이동에 이름이 없어서 `FirebaseAnalyticsObserver` 는 하위 화면을 못 남긴다. `test/util/analytics_screen_view_test.dart` 가 막는다 |
| 개발 빌드는 보내지 않는다 | 릴리즈 빌드이면서 `--dart-define=ENV=prod` 일 때만 수집한다 (`AppAnalytics.shouldCollect`) |

## 2. 공통 파라미터 사전

같은 뜻이면 이벤트가 달라도 같은 이름을 쓴다. 그래야 맞춤 측정기준 하나로 여러 이벤트를 가를 수 있다.

### 문자열 (맞춤 측정기준으로 등록)

| 파라미터 | 뜻 | 값 예 |
|---|---|---|
| `source` | 어디서 시작했나 | `mypage`, `level_up`, `detail`, `list`, `drag`, `selection`, `auto`, `menu`, `member`, `guest` |
| `mode` | 어떤 방식으로 했나 | `single`, `multi`, `offline`, `canvas`, `tag`, `title`, `photo`, `scan` |
| `result` | 결과 | `success`, `fail`, `dismissed`, `rejected`, `unknown` |
| `method` | 로그인 방식 | `google`, `apple`, `kakao`, `guest` |
| `category` | 능력치 분류 | `attendance`, `note_write`, `problem_practice`, `note_practice`, `total` |
| `color` | 테마 색 이름 | `진핑크`, `라일락` |
| `item_key` | 치장 아이템 키 | `hat_graduate` |
| `slot` | 치장 자리 | `HEAD`, `BACKGROUND` |
| `mission_code` | 미션 코드 | `DAILY_NOTE_WRITE` |
| `period` | 기간 | `daily`, `weekly`, `monthly`, `total` |
| `mood` | 고른 기분 키 | 이모지 키, 안 골랐으면 `none` |
| `answer_status` | 복습 정답 여부 | `correct`, `wrong`, `partial` |
| `notification_type` | 알림 종류 | `review_due`, `reengagement`, `shared_problem` 등 |
| `entry` | 알림을 받은 앱 상태 | `foreground`, `background`, `terminated` |
| `tab` | 탭 | `problem`, `answer`, `history`, `ranking`, `challenge` |
| `reason` | 막힌 이유 | `title`, `image` |

### 숫자 (필요할 때 맞춤 측정항목으로 등록)

| 파라미터 | 뜻 |
|---|---|
| `count` | 몇 개를 한 번에 했나 |
| `problem_count` | 문제 수 |
| `image_count` | 이미지 수 |
| `duration_sec` | 걸린 시간(초) |
| `required_level` | 잠금 해제에 필요한 레벨 |
| `level_gap` | 지금 레벨에서 몇 레벨 남았나 |
| `reward_value` | 받은 XP |

`true` / `false` 값(예: `via_canvas`, `used_stylus`)은 문자열로 들어가므로 측정기준으로 등록한다.

## 3. 이벤트

**굵은 이름**은 이번에 새로 넣었거나 파라미터를 채운 것이다. 나머지는 예전부터 있던 것이고, 이어서 볼 수 있게 이름을 바꾸지 않았다.

### 가입과 로그인

| 이벤트 | 언제 | 파라미터 |
|---|---|---|
| **`login_start`** | 로그인 버튼을 눌렀을 때 | `method` |
| `login` | 로그인이 끝까지 성공했을 때. 예전에는 토큰을 받기 전에 남겨 실패도 셌다 | `method` |
| **`sign_up`** | 로그인 성공 시 계정이 10분 안에 만들어졌으면. 서버가 가입 여부를 알려 주지 않아 `createdAt` 으로 판단한다 | `method` |
| **`login_fail`** | 로그인 중 예외가 났을 때 | `source`, `error` (예외 타입) |
| **`logout`** | 회원이 로그아웃했을 때 | `method` |
| `user_delete` | 계정을 지웠을 때. 게스트 로그아웃도 계정을 지워서 `trigger` 로 가른다 | `method`, `trigger` (`withdraw`, `guest_logout`) |
| **`splash_unreachable`** | 첫 화면에서 서버에 닿지 못했을 때 | `retry` |

### 오답노트 작성

| 이벤트 | 언제 | 파라미터 |
|---|---|---|
| `problem_created` | 등록 성공. 다중 등록도 여기로 온다 | `mode`, `count`, 단일이면 `problem_image_count`, `answer_image_count`, `tag_count`, `has_memo`, `auto_title` |
| `problem_updated` | 수정 성공 | 위 이미지와 태그 값 |
| **`problem_register_blocked`** | 제목이나 이미지가 없어 막혔을 때 | `reason` |
| **`image_picked`** | 카메라나 앨범에서 실제로 받았을 때. `image_select_*` 는 고른 순간이라 열었다 닫은 것도 센다 | `source` (`camera`, `gallery`), `count` |
| **`camera_capture`** | 촬영하거나 문서 스캔을 마쳤을 때 | `mode` (`photo`, `scan`), `flash`, `multiple`, `count` |
| **`tag_recommend_shown`** | AI 추천 태그를 받았을 때 | `count`, `with_image` |
| **`tag_recommend_apply`** | 추천 태그를 눌러 붙였을 때 | `mode` |
| **`tag_select_confirm`** | 태그 선택 화면을 확정했을 때 | `count`, `total_tag_count` |
| `tag_created` / **`tag_deleted`** | 태그를 만들거나 지웠을 때 | 지우기는 `count` |

## 4. 유저 속성

| 속성 | 값 | 언제 바뀌나 |
|---|---|---|
| `login_method` | 로그인 방식 | 유저 정보를 받을 때 |
| `total_study_level` 외 레벨 4개 | 숫자 | 유저 정보를 받을 때 |
| `notification_enabled` | `true` / `false` | 유저 정보를 받을 때 |
| `days_since_signup` | 가입 후 경과일 | 유저 정보를 받을 때 |
| `has_profile_image` | `true` / `false` | 유저 정보를 받을 때 |
| **`theme_color`** | 지금 쓰는 테마 이름 | 앱을 켤 때, 테마를 바꿀 때. 기기 값이라 로그아웃해도 남긴다 |

유저 ID 는 서버 내부 번호다. 로그아웃하면 지운다.

`screen_view` 의 `firebase_screen` 값이다. 직전 화면(`firebase_previous_screen`)이 자동으로 붙어서, 어디서 들어왔는지는 따로 남기지 않는다.

| 구분 | 화면 이름 |
|---|---|
| 하단 탭 | `DirectoryScreen`, `ProblemPracticeScreen`, `CharacterScreen`, `StudyRoomScreen`, `SettingScreen` |
| 작성 | `ProblemRegisterScreen`, `ProblemEditScreen`, `MultiProblemRegisterScreen`, `TagSelectionScreen`, `CameraScreen` |
| 상세와 복습 | `ProblemDetailScreen`, `FullScreenImage`, `ProblemSolveCanvasScreen`, `ProblemSolveRegisterScreen`, `AnswerImagesScreen`, `ReviewDueScreen`, `TagProblemSearchScreen` |
| 복습 세트 | `PracticeProblemSelectionScreen`, `PracticeTitleWriteScreen`, `PracticeDetailScreen`, `PracticeCompletionScreen` |
| 꾸미기와 보상 | `CosmeticClosetScreen`, `MissionScreen`, `MissionHistoryScreen`, `AchievementScreen`, `AchievementCardScreen` |
| 스터디룸 | `StudyRoomCreateScreen`, `StudyRoomJoinScreen`, `StudyRoomDetailScreen`, `StudyRoomEditScreen`, `ProblemPickerScreen`, `SharedProblemDetailScreen` |
| 그 밖 | `SplashScreen`, `LoginScreen`, `MyPageSettingsScreen`, `LearningCalendarScreen`, `ReviewReportScreen` |

## 6. 콘솔에서 해 둘 것

코드만으로는 끝나지 않는다. 아래는 Google Analytics 관리 화면에서 한 번 해 둔다.

| 할 일 | 위치 | 내용 |
|---|---|---|
| 주요 이벤트 지정 | 관리 → 이벤트 | `sign_up`, `problem_created`, `problem_repeat`, `practice_session_completed` 에 별표. `theme_color_change` 는 이제 제대로 들어오니 그대로 둔다 |
| 맞춤 측정기준 등록 | 관리 → 맞춤 정의 | 2절의 문자열 파라미터 16개, 그리고 `via_canvas`, `used_stylus`, `tools`, `improvements`, `trigger`, `achievement_id`, `step_id` |
| 유저 범위 측정기준 등록 | 관리 → 맞춤 정의 → 범위: 사용자 | 4절의 속성 전부 |
| 이벤트 데이터 보관 기간 | 관리 → 데이터 보관 | 2개월에서 14개월로. 탐색 분석이 보관 기간까지만 된다 |

맞춤 측정기준은 **등록한 날부터** 쌓인다. 앱이 먼저 나가도 되지만, 등록이 늦으면 그 사이 값은 보고서에서 못 쓴다.

## 7. 궁금한 것별로 볼 곳

| 궁금한 것 | 볼 이벤트 |
|---|---|
| 새로 온 사람이 어디서 빠지나 | 탐색 → 유입경로: `first_open` → `sign_up` → `tutorial_complete` → `problem_created` → `problem_repeat` |
| 어떤 테마를 갖고 싶어 하나 | `theme_locked_tap` 을 `color` 로. 적용은 `theme_color_change`, 지금 쓰는 분포는 유저 속성 `theme_color` |
| 어떤 치장이 인기인가 | 수요는 `cosmetic_locked_tap`, 관심은 `cosmetic_try_on`, 실제로 입는 것은 `cosmetic_equip` 을 `item_key` 로 |
| 옷장 저장이 어려운가 | `cosmetic_discard` 대 `cosmetic_save` |
| 필기 캔버스 기능이 쓰이나 | `canvas_submit` 의 `tools`, `used_stylus`, `color_changed`. 중간에 그만두는 비율은 `canvas_abandon` |
| 복습을 어떻게 하나 | `problem_repeat` 의 `answer_status`, `duration_sec`, `mood`, `via_canvas` |
| AI 기능이 쓸모 있나 | `tag_recommend_apply` / `tag_recommend_shown`, `problem_analysis_result` 의 `result` |
| 어떤 알림이 사람을 데려오나 | `push_open` 을 `notification_type` 으로 |
| 기능별로 얼마나 쓰이나 | 보고서 → 참여도 → 페이지 및 화면에서 화면 이름별 사용자 수 |

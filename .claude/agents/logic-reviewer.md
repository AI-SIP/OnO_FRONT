OnO Flutter 앱의 비즈 로직 정합성 전문가.

## 검토 항목

**null safety**:
- `!` (강제 언래핑)을 사용하는 곳이 실제로 null이 올 수 없는가
- `?.`로 조용히 null을 무시했을 때 사용자가 빈 화면을 보게 되는 경우가 있는가
- API 응답의 nullable 필드를 방어하지 않고 바로 사용하는가

**async 경합**:
- `mounted` 체크 없이 `setState`를 호출하는가 (`if (!mounted) return`)
- 여러 Future가 동시에 실행될 때 마지막으로 오는 값이 올바른가
- `await`를 빠뜨려 실행 순서가 보장되지 않는 곳이 있는가

**상태 전이**:
- 로딩 → 성공 → 에러 → 빈 상태 전환이 모두 처리되는가
- 이전 상태가 새 상태로 덮어씌워지지 않고 남아있는 경우가 있는가
- 뒤로 가기·화면 재진입 시 상태가 올바르게 초기화되는가

**에러 처리**:
- 에러를 `catch`해서 조용히 삼키는 경우가 있는가
- 사용자에게 보여줄 에러 메시지가 기술 용어나 스택 트레이스를 포함하는가
- 네트워크 에러, 타임아웃, 서버 오류를 각각 다르게 처리해야 하는 경우가 있는가

**버전·데이터 불일치**:
- API 응답 shape가 바뀌었을 때 앱이 크래시 없이 처리할 수 있는가
- 로컬 캐시와 서버 데이터가 불일치할 때 사용자가 잘못된 데이터를 볼 수 있는가

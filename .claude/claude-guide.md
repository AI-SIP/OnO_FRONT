## 1. 설정 파일 구조

```
OnO_FRONT/
├── CLAUDE.md                          ← 프로젝트 지침 (Claude가 항상 읽음)
├── AGENTS.md                          ← 구버전 AI 에이전트 지침 (참고용)
└── .claude/
    ├── settings.local.json            ← 이 레포 전용 권한 설정 (git 제외)
    ├── commands/                      ← 커스텀 슬래시 명령어
    │   ├── analysis.md
    │   ├── plan.md
    │   ├── feat.md
    │   ├── check.md
    │   ├── commit.md
    │   ├── pr.md
    │   └── explain.md
    └── agents/                        ← 전문가 서브에이전트
        ├── code-tracer.md
        ├── perf-reviewer.md
        ├── logic-reviewer.md
        ├── side-effect-checker.md
        ├── permission-auditor.md
        └── report-writer.md

~/.claude/
└── settings.json                      ← 글로벌 설정 (알림 훅 포함)
```

**설정 우선순위**: 글로벌(`~/.claude/`) → 프로젝트(`.claude/settings.json`) → 로컬(`.claude/settings.local.json`)

## 2. 커스텀 명령어 7종

Claude Code 프롬프트 입력창에서 `/명령어` 형태로 호출한다.

### 명령어 한눈에 보기

| 명령어 | 목적 | 코드 수정 | 커밋 실행 |
|---|---|:---:|:---:|
| `/analysis` | 문제 원인 규명 및 병렬 조사 | ✗ | ✗ |
| `/plan` | 구현 명세서 작성 | ✗ | ✗ |
| `/feat` | plan 기반 기능 구현 | ✓ | ✗ |
| `/check` | 다관점 검증 및 위험도 분류 | ✗ | ✗ |
| `/commit` | 커밋 단위 및 메시지 제안 | ✗ | ✗ |
| `/pr` | PR 초안 작성 | ✗ | ✗ |
| `/explain` | 코드 흐름·원리 설명 | ✗ | ✗ |

---

### `/analysis [문제 설명]`

**언제**: 버그가 생겼는데 원인을 모를 때, 특정 동작이 왜 그렇게 되는지 파악할 때.

**동작 흐름**:
1. 문제 상황, 원하는 동작, 관련 경로를 먼저 확인 (이미 알면 생략)
2. 문제를 4개 차원으로 분해 (위젯·상태 흐름 / API·데이터 / 비동기·타이밍 / 플랫폼 차이)
3. `code-tracer` 에이전트와 병렬로 각 차원 조사
4. 결과를 교차 반증해 모순·허점 제거
5. 요약 + 근거(`파일:라인`) + 원인 목록(확신도 포함) 보고

**사용 예**:
```
/analysis 오답노트 목록에서 간헐적으로 빈 화면이 뜨는 현상
/analysis 로그인 후 첫 화면 진입 시 API가 두 번 호출됨
```

**출력**:
```
## 요약
## 근거 (파일:라인)
## 원인 목록 (확신도: 높음/중간/낮음)
## 확인이 필요한 부분
```

---

### `/plan <기능 설명>`

**언제**: 새 기능을 구현하기 전에 명세서를 먼저 만들 때. `/feat` 실행 전에 항상 거치는 것을 권장.

**동작 흐름**:
1. `docs/`에서 관련 문서 먼저 확인
2. `code-tracer` 에이전트로 관련 위젯·상태 흐름 파악
3. `docs/` 하위에 기능명 폴더 생성 후 markdown 명세서 작성
4. 명세서 완성 후 검토 요청 → `/feat` 전에 대기

**저장 위치**: `docs/<기능명>/명세서.md` (기존 한글 폴더 스타일 따름)

**명세서 구성**: 요구사항 / 영향 범위 / API·상태 관리 / 반응형 고려사항 / 구현 단계(순서) / 배포 리스크 / 검증 방법

**사용 예**:
```
/plan 오답 복습 달력 주간 뷰 추가
/plan PDF 내보내기 로딩 상태 개선
```

> ⚠️ 코드를 수정하지 않는다. 명세서만 작성하고 검토를 기다린다.

---

### `/feat [명세서 경로 또는 기능명]`

**언제**: `/plan`으로 만든 명세서를 승인한 뒤 실제 구현할 때.

**동작 흐름**:
1. 어떤 명세서를 기준으로 할지 확인 (불명확하면 물어봄)
2. 명세서 + 현재 코드 확인 (차이가 있으면 설명)
3. 명세서 구현 단계를 순서대로 실행
4. 구현 후 `dart format .` → `flutter analyze` 자동 실행
5. 변경 내용·사용자 영향·반응형 처리·검증 결과·리스크·추천 커밋 보고

**구현 규칙**:
- 명세서 범위만 수정 (무관한 리팩터링·포맷팅 금지)
- 주변 코드 스타일·패턴 그대로 따름
- null safety, async, 에러/로딩/빈 상태 챙김
- API 계약 불명확 시 임의 단정 금지

**커밋 메시지 형식** (제안만, 실행 안 함):
```
[Feat] 한 줄 요약 - 상세1 상세2
```

---

### `/check [커밋 해시]`

**언제**: 구현 완료 후 출시 전에 코드를 다각도로 검증할 때. 커밋 해시 없으면 현재 변경사항만 검토.

**동작 흐름**:
1. `git diff` 로 변경된 파일과 사용자 흐름 파악
2. 아래 에이전트를 **병렬** 실행:
   - `perf-reviewer`: 불필요한 rebuild, jank, 메모리 이슈
   - `logic-reviewer`: null safety, async 경합, 상태 전이, 에러 처리
   - `side-effect-checker`: API 중복 호출, 로컬 저장 부작용, FCM
   - `permission-auditor`: 화면 접근 제어 (UI 변경 있을 때)
3. `flutter analyze` 실행
4. 에이전트 결과를 교차 반증
5. 위험도 분류 보고

**사용 예**:
```
/check                   ← 현재 변경사항 검토
/check a1b2c3d           ← 해당 커밋부터 HEAD까지 검토
```

**출력 위험도**:
- 🔴 즉시 수정 필요
- 🟠 출시 전 수정 권장
- 🟡 주의 필요 (트레이드오프 존재)
- 🟢 이상 없음

---

### `/commit [맥락 설명]`

**언제**: 여러 변경사항이 쌓였을 때 어떻게 커밋을 나눌지 정리가 필요할 때.

**동작 흐름**:
1. `git status` / `git diff` / `git diff --staged` 확인
2. 기능 추가·버그 수정·스타일·설정 변경 등을 논리 단위로 분리
3. 각 단위에 대해 `git add <파일>` + `git commit -m "..."` 형태로 제안

> ⚠️ **커밋을 직접 실행하지 않는다.** 제안만 한다.

**출력 예**:
```
## 커밋 1
git add lib/screens/calendar_screen.dart
git commit -m "[Feat] 학습 달력 주간 뷰 추가 - 태블릿 레이아웃 대응"

## 커밋 2
git add lib/widgets/calendar_item.dart
git commit -m "[Fix] 달력 아이템 날짜 null 처리 추가"
```

---

### `/pr <기준 커밋 해시>`

**언제**: 기능 브랜치 작업 완료 후 PR 초안을 빠르게 만들 때.

**동작 흐름**:
1. `git log <해시>..HEAD` + `git diff <해시>..HEAD` 로 변경 내역 파악
2. `.github/PULL_REQUEST_TEMPLATE.md` 양식 확인
3. `/plan` 명세서와 같은 `docs/` 폴더에 PR 문서 저장
4. 변경 요약·주요 구현·반응형 대응·검증 결과·배포 리스크 포함

> ⚠️ 코드를 수정하거나 PR을 실제로 생성하지 않는다.

---

### `/explain <파일명, 위젯명, 또는 기능 설명>`

**언제**: 낯선 코드를 이해할 때, 특정 위젯의 데이터가 어디서 오는지 파악할 때, 팀원에게 설명 전 흐름을 정리할 때.

**동작 흐름**:
1. `code-tracer` 에이전트와 함께 진입점부터 추적
   - 위젯 트리: 어디서 시작 → 어느 자식까지
   - 상태 관리: 상태 정의 → 변경 트리거 → UI 반영
   - API 경로: UI 이벤트 → 서비스 → 엔드포인트
2. 단계별로 `파일:라인` 인용 + 설계 의도·트레이드오프 설명
3. 흐름 요약 + 핵심 설계 이유 + 주의할 동작 정리

**사용 예**:
```
/explain lib/screens/review_screen.dart
/explain 오답노트 목록 로딩 흐름
/explain AuthProvider
```

## 3. 전문가 에이전트 6종

명령어 내부에서 Claude가 자동으로 호출하는 서브에이전트. 직접 호출할 수도 있지만 보통 명령어가 알아서 쓴다.

모든 검증·조사 에이전트는 **읽기 전용** — 코드를 수정하거나 커밋하지 않는다.

---

### `code-tracer`

**역할**: 위젯 트리·상태 관리·API 호출 흐름을 지도로 만든다.

**사용하는 명령어**: `/analysis`, `/plan`, `/feat`, `/explain`

**추적 방향**:
- 위젯 트리: 진입 위젯 → 자식 → 상태 소비 위젯
- 상태 관리: 상태 정의 위치 → 변경 트리거 → UI 반영
- API 호출: UI 이벤트 → 서비스/레포지토리 → HTTP → 엔드포인트

**출력**:
```
[진입점 파일:라인]
  └→ [다음 단계 파일:라인] — 설명
       └→ [다음 단계 파일:라인] — 설명
```

---

### `perf-reviewer`

**역할**: Flutter 성능 문제를 찾는다.

**사용하는 명령어**: `/check`

**검토 항목**:
- **불필요한 rebuild**: `setState` 범위, `const` 분리 미적용, 너무 넓은 watch
- **jank**: `build()` 안 무거운 연산, 메인 스레드 동기 I/O
- **메모리·이미지**: 컨트롤러 `dispose` 누락, Stream 누수, 이미지 캐시 미사용
- **리스트**: `ListView` → `ListView.builder` 미전환

---

### `logic-reviewer`

**역할**: 비즈 로직 정합성을 검증한다.

**사용하는 명령어**: `/check`

**검토 항목**:
- **null safety**: `!` 강제 언래핑 위험, `?.` 조용한 무시, API nullable 미방어
- **async 경합**: `mounted` 체크 누락, Future 순서 미보장, `await` 누락
- **상태 전이**: 로딩→성공→에러→빈 상태 전환 누락, 재진입 시 초기화 여부
- **에러 처리**: catch 후 삼킴, 기술적 에러 메시지 노출

---

### `side-effect-checker`

**역할**: 의도치 않은 외부 영향과 부작용을 찾는다.

**사용하는 명령어**: `/check`

**검토 항목**:
- **API 중복 호출**: build/initState 중복, 버튼 debounce 미적용, 페이지네이션 중복
- **로컬 저장**: SharedPreferences 덮어씌움, 민감 정보 평문 저장
- **FCM**: 토큰 갱신 중복 실행, 실사용자 알림 발송 경로 영향
- **화면 이탈**: 타이머·구독 미정리, 이전 세션 상태 잔류

---

### `permission-auditor`

**역할**: 화면 접근 제어와 인증 흐름을 검증한다.

**사용하는 명령어**: `/check` (UI 변경 포함 시)

> 데이터 격리(남의 오답노트 접근 차단)는 백엔드 책임. 여기서는 앱 화면·네비게이션 레벨만 검토.

**검토 항목**:
- **화면 접근**: 비로그인 사용자가 인증 필요 화면 접근 가능 여부, 딥링크 우회
- **토큰·세션**: 만료 시 리디렉션 여부, 로그아웃 시 정리 여부
- **라우팅**: 뒤로 가기로 인증 전 화면 접근 가능 여부

---

### `report-writer`

**역할**: 기술적 변경사항을 비기술적 언어로 보고서화한다.

**사용하는 명령어**: `/pr` (내부적으로 활용)

**작성 원칙**: 존댓말, 핵심 위주, 기술 용어 최소화, Before/After 표 활용

---

### 명령어 ↔ 에이전트 매핑

| 명령어 | 사용 에이전트 |
|---|---|
| `/analysis` | `code-tracer` |
| `/plan` | `code-tracer` |
| `/feat` | `code-tracer` |
| `/check` | `perf-reviewer`, `logic-reviewer`, `side-effect-checker` (+UI 변경 시 `permission-auditor`) |
| `/explain` | `code-tracer` |
| `/pr` | `report-writer` |
| `/commit` | (없음 — 경량 명령) |

## 4. 권한 설정

`.claude/settings.local.json` — 이 레포에서만 적용, git에 포함되지 않음.

### 자동 허용 (승인 없이 바로 실행)

| 허용 항목 | 이유 |
|---|---|
| `Read`, `Grep`, `Glob` | 읽기 전용 — 위험 없음 |
| `Bash(git status/diff/log/show/branch)` | 읽기 전용 git 조회 |
| `Bash(ls)` | 디렉토리 조회 |
| `Bash(flutter analyze)` | 정적 분석 — 부작용 없음 |
| `Bash(flutter test)` | 테스트 실행 |
| `Bash(flutter build)` | 빌드 |
| `Bash(flutter run)` | 앱 실행 |
| `Bash(dart format)` | 포맷팅 |
| `Bash(find . *)` | 파일 탐색 |

### 차단 (실행 불가)

| 차단 항목 | 이유 |
|---|---|
| `Bash(git push --force)` | 원격 히스토리 파괴 위험 |
| `Bash(git reset --hard)` | 로컬 변경사항 파괴 위험 |
| `Bash(git clean)` | 추적 안 된 파일 삭제 위험 |

> `git push`(일반)는 차단 목록에 없다 — Claude가 push 제안 시 매번 승인 프롬프트가 뜬다.

## 5. 알림 훅

`~/.claude/settings.json` — 모든 프로젝트에 적용되는 글로벌 설정.

macOS 시스템 알림(`osascript`)을 사용한다. 추가 모듈 설치 불필요.

| 이벤트 | 트리거 시점 | 알림 메시지 |
|---|---|---|
| `Stop` | Claude가 작업을 완료했을 때 | "작업 완료" |
| `Notification` | 권한 승인·입력이 필요할 때 | "확인이 필요해요" |

두 훅 모두 `async: true` — 알림이 Claude 응답을 블로킹하지 않는다.

**설정 확인·수정**: `/hooks` 메뉴에서 언제든 변경 가능.

## 6. 작업 파이프라인 권장 흐름

### 일반 기능 구현

```
/plan <기능>  →  검토  →  /feat  →  /check  →  /commit  →  /pr
```

1. `/plan` — 명세서 작성, 코드 건드리지 않음
2. **검토** — 명세서 내용 확인 후 `/feat` 진행 승인
3. `/feat` — 구현 + `dart format` + `flutter analyze` 자동 실행
4. `/check` — 구현 결과 다관점 검증 (4개 에이전트 병렬)
5. `/commit` — 논리 단위 분할 + 메시지 제안
6. `/pr <기준 커밋>` — PR 초안 작성

### 버그 조사

```
/analysis <현상>  →  원인 파악  →  /feat  →  /check  →  /commit
```

### 코드 이해

```
/explain <대상>  →  흐름 파악
```

### 단계별 검토 강도

| 단계 | 강도 | 이유 |
|---|---|---|
| `/plan` 결과 검토 | 🔴 최고 | 방향이 잘못되면 구현 전체가 낭비 |
| `/feat` 완료 후 | 🟠 높음 | 코드가 명세서대로 나왔는지 확인 |
| `/check` 결과 | 🟡 중간 | 도구가 잡은 문제를 판단 |
| `/pr` 초안 | 🟢 낮음 | 문서 수준 확인 |

## 부록: 커밋 메시지 형식

```
[태그] 한 줄 요약 - 상세1 상세2
```

| 태그 | 사용 시점 |
|---|---|
| `[Feat]` | 새 기능 추가 |
| `[Fix]` | 버그 수정 |
| `[Refactor]` | 동작 변경 없는 코드 개선 |
| `[Chore]` | 빌드·설정·의존성 변경 |
| `[Test]` | 테스트 코드 추가·수정 |
| `[Docs]` | 문서 변경 |

**예시**:
```
[Feat] 학습 달력 주간 뷰 추가 - 태블릿 레이아웃 대응 빈 상태 처리
[Fix] 오답노트 PDF 내보내기 오류 수정 - null 응답 방어 로딩 상태 개선
[Chore] flutter 3.22로 업그레이드
```

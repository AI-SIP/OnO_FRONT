---
description: 현재 변경사항을 논리 단위로 나눠 커밋까지 실행
argument-hint: "[맥락 설명, 생략 가능]"
---

현재 변경사항을 논리 단위로 분리하여 커밋 메시지를 결정하고, **실제로 커밋을 실행한다.**

**1단계 – 변경사항 파악**
```
git status
git diff
git diff --staged
```

**2단계 – 논리 단위 분할**
변경사항을 논리적으로 분리 가능한 단위로 나눈다.
- 기능 추가, 버그 수정, 스타일 수정, 설정 변경은 각각 분리
- 하나의 커밋은 하나의 이유로만 변경된 내용을 포함
- 너무 잘게 쪼개지 않되, 리뷰 가능한 크기로

**3단계 – 커밋 메시지 결정**
각 단위에 대해 아래 형식으로 메시지를 정한다. 브랜치에 이슈 번호가 있으면 끝에 `(#번호)` 를 붙인다.

```
[태그] 한 줄 요약 - 상세1 상세2 (#이슈번호)
```

태그: `[Feat]` / `[Fix]` / `[Refactor]` / `[Chore]` / `[Test]` / `[Docs]`

`/commit` 호출 자체가 커밋 요청이므로 따로 확인을 받지 않고 순서대로 실행한다. 다만 아래 경우는 커밋하지 않고 보고한다.
- 현재 브랜치가 `main` 또는 `develop`
- 비밀 파일(`.env`, 서명 파일)이나 빌드 산출물이 변경분에 섞여 있음
- 요청과 무관해 보이는 사용자의 다른 변경이 섞여 있어 어디까지 커밋할지 불분명함

**4단계 – 커밋 실행**
확정된 단위 순서대로 아래 패턴으로 실행한다.

```
git add <파일 목록>
git commit -m "[태그] 한 줄 요약 - 상세1 상세2 (#이슈번호)"
```

커밋 후 `git log --oneline -5`로 결과를 확인하고 보고한다. push 와 PR 생성은 `/pr` 에서 한다.

argument-hint: "<기능 설명>"
---

$ARGUMENTS 기능에 대한 구현 명세서를 작성한다.

**코드를 수정하지 않는다.**

**1단계 – 현황 파악**
- `docs/`에 관련 문서가 있는지 먼저 확인한다.
- 관련 위젯·파일·상태 관리 흐름을 `code-tracer` 에이전트로 확인한다.
- API 연동이 필요하면 요청/응답 shape를 확인한다. 불명확하면 "확인 필요"로 표시한다.

**2단계 – 명세서 작성**
`docs/` 아래에 기능명으로 새 폴더를 만들고, 그 안에 markdown 명세서를 작성한다.
폴더명·파일명은 기존 `docs/`의 한글 스타일을 따른다.

명세서 구성:
```markdown
# <기능명> 구현 명세서

## 요구사항
- 사용자 관점에서 어떤 동작이 필요한가

## 영향 범위
- 변경·추가되는 파일/위젯
- 영향받는 사용자 흐름

## API/상태 관리
- 사용할 API 엔드포인트와 응답 필드
- 상태 관리 방식 (Provider/Riverpod/Bloc 등)

## UI 반응형 고려사항
- 폰/태블릿/가로화면에서 처리할 내용

## 구현 단계 (순서대로)
1. ...
2. ...

## 배포 리스크
- 릴리즈 후 되돌리기 어려운 변경이 있는가

## 검증 방법
- flutter analyze
- 확인해야 할 화면/시나리오
```

**3단계 – 확인 대기**
명세서 작성 후 사용자에게 검토를 요청하고 `/feat` 실행 전에 대기한다.

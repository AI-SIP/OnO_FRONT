---

다음 세 가지를 먼저 확인한다. 이미 알고 있으면 건너뛴다.
1. 어떤 문제/현상이 발생하고 있는가?
2. 원하는 동작은 무엇인가?
3. 관련 파일·위젯·API 경로가 있으면 알려달라.

확인 후 아래 순서로 진행한다.

**1단계 – 조사 각도 분해**
문제를 다음 차원으로 분해한다.
- 위젯 트리·상태 흐름: 어디서 상태가 만들어지고, 어디서 깨지는가
- API/데이터 흐름: 요청 시점, 응답 shape, null 가능성
- 비동기·타이밍: async 경합, Future/Stream 처리 순서
- 플랫폼 차이: Android/iOS, 폰/태블릿 동작 차이

**2단계 – 병렬 조사**
각 차원을 `code-tracer` 에이전트와 함께 병렬로 조사한다.
- 코드를 수정하지 않는다.
- 근거는 반드시 `파일:라인` 형식으로 인용한다.
- 추정하지 않는다. 확인되지 않은 내용은 "확인 필요"로 표시한다.

**3단계 – 교차 반증**
각 조사 결과를 서로 대조해 모순·허점을 찾는다.
- A 원인이 맞다면 B 동작이 설명되는가?
- 재현 조건과 조사 결과가 일치하는가?

**4단계 – 종합 보고**
아래 형식으로 정리한다.
```
## 요약
한두 줄로 핵심 원인

## 근거
- 파일:라인 – 설명
- ...

## 원인 목록 (확신도 포함)
1. [높음] ...
2. [중간] ...

## 확인이 필요한 부분
- ...
```

**규칙**: 이 명령은 읽기 전용이다. 코드를 수정하거나 커밋하지 않는다.
